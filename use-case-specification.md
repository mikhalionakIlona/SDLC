# Дополнительные спецификации вариантов использования NutriFlow

## 1. Актёры

| Актор | Описание |
|---|---|
| Пользователь | Владелец Android-устройства, который ведёт дневник питания и учёт воды, задаёт цели и просматривает статистику |
| Open Food Facts | Внешний сервис, предоставляющий сведения о продукте по штрихкоду |
| Система уведомлений Android | Системный компонент, отображающий напоминания о воде |

## 2. Прецеденты

### UC-01 «Добавить приём пищи вручную»

- **Краткое описание:** пользователь вручную добавляет продукт в приём пищи за выбранную дату.
- **Предусловия:** приложение запущено, открыт экран дневника.
- **Основной поток:**
  1. Пользователь нажимает кнопку добавления.
  2. Система открывает экран выбора продукта и массы.
  3. Пользователь выбирает продукт из списка или создаёт новый.
  4. Пользователь указывает массу и тип приёма пищи.
  5. Система рассчитывает калории и БЖУ пропорционально массе.
  6. Пользователь подтверждает добавление.
  7. Система сохраняет запись в Room и пересчитывает дневные итоги.
- **Альтернативный поток А1 (продукт не выбран):** система отображает сообщение об ошибке.
- **Постусловия:** запись сохранена, дневные итоги обновлены.

### UC-02 «Сканировать штрихкод»

- **Краткое описание:** пользователь сканирует штрихкод продукта камерой, система находит продукт в локальной базе или в Open Food Facts и добавляет его в приём пищи.
- **Предусловия:** приложение запущено, пользователь находится на экране добавления продукта, камера доступна.
- **Основной поток:**
  1. Пользователь нажимает кнопку сканирования.
  2. Система запрашивает разрешение на использование камеры (если не предоставлено).
  3. CameraX передаёт изображение, ZXing распознаёт штрихкод.
  4. Система выполняет поиск продукта в локальной базе.
  5. Если продукт найден локально, система отображает его сведения.
  6. Если продукт не найден, система выполняет запрос к Open Food Facts.
  7. Система отображает полученные сведения для подтверждения.
  8. Пользователь подтверждает добавление, система сохраняет запись в Room.
- **Альтернативный поток А1 (разрешение не предоставлено):** система отображает сообщение и предлагает ручной ввод.
- **Альтернативный поток А2 (продукт не найден):** система сообщает об отсутствии продукта и предлагает создать его вручную.
- **Поток ошибки Е1 (нет сети):** система сообщает об ошибке сети и предлагает ручной ввод.
- **Постусловия:** запись о приёме пищи сохранена в локальной базе, дневные итоги пересчитаны.

### UC-03 «Найти продукт в Open Food Facts»

- **Краткое описание:** система по штрихкоду запрашивает сведения о продукте во внешнем каталоге.
- **Предусловия:** штрихкод распознан, продукт отсутствует в локальной базе, сеть доступна.
- **Основной поток:**
  1. Адаптер формирует GET-запрос к Open Food Facts.
  2. Сервис возвращает JSON с данными продукта.
  3. Адаптер преобразует JSON в модель FoodProduct.
  4. Репозиторий возвращает продукт в UI.
- **Поток ошибки Е1 (сеть недоступна):** система сообщает об ошибке и предлагает ручной ввод.
- **Поток ошибки Е2 (продукт не найден в OFF):** система сообщает об отсутствии продукта.
- **Постусловия:** продукт передан в UI для подтверждения.

### UC-04 «Добавить воду»

- **Краткое описание:** пользователь фиксирует объём выпитой воды.
- **Предусловия:** приложение запущено, открыт экран воды.
- **Основной поток:**
  1. Пользователь нажимает кнопку быстрого ввода (+150, +250, +500 мл) или вводит произвольный объём.
  2. Система сохраняет WaterEntry в Room.
  3. Система пересчитывает дневную сумму и процент цели.
- **Альтернативный поток А1 (отмена):** пользователь отменяет последнее добавление.
- **Постусловия:** запись сохранена, прогресс обновлён.

### UC-05 «Настроить дневные цели»

- **Краткое описание:** пользователь задаёт целевые значения калорий и воды.
- **Предусловия:** приложение запущено, открыт экран целей.
- **Основной поток:**
  1. Пользователь вводит целевую калорийность и целевой объём воды.
  2. Система сохраняет DailyGoal в Room.
  3. Система пересчитывает прогресс на экранах дневника и воды.
- **Альтернативный поток А1 (некорректное значение):** система отображает сообщение об ошибке.
- **Постусловия:** цели сохранены, прогресс обновлён.

### UC-06 «Настроить напоминания»

- **Краткое описание:** пользователь включает напоминания и задаёт расписание.
- **Предусловия:** приложение запущено, разрешение на уведомления предоставлено.
- **Основной поток:**
  1. Пользователь включает напоминания и задаёт интервал.
  2. Система сохраняет ReminderSettings в Room.
  3. WorkManager планирует фоновую задачу.
  4. Система уведомлений Android отображает напоминания по расписанию.
- **Альтернативный поток А1 (разрешение не предоставлено):** система сообщает о необходимости разрешения.
- **Постусловия:** задача запланирована, напоминания активны.

### UC-07 «Просмотреть статистику»

- **Краткое описание:** пользователь просматривает графики калорий и воды за 7 или 30 дней.
- **Предусловия:** приложение запущено, открыт экран статистики.
- **Основной поток:**
  1. Пользователь выбирает период (7 или 30 дней).
  2. Система агрегирует данные из Room.
  3. MPAndroidChart отображает графики.
- **Постусловия:** графики отображены.

### UC-08 «Экспортировать дневник в CSV»

- **Краткое описание:** пользователь сохраняет дневник питания в CSV-файл за выбранный период.
- **Предусловия:** приложение запущено, открыт экран экспорта.
- **Основной поток:**
  1. Пользователь выбирает период.
  2. Система формирует CSV из локальной базы.
  3. Система сохраняет файл средствами Android.
- **Поток ошибки Е1 (нет доступа к хранилищу):** система сообщает об ошибке.
- **Постусловия:** файл сохранён на устройстве.

### UC-09 «Просмотреть дневные итоги»

- **Краткое описание:** пользователь просматривает сумму калорий, БЖУ и воды за выбранную дату.
- **Предусловия:** приложение запущено, открыт экран дневника.
- **Основной поток:**
  1. Пользователь выбирает дату.
  2. Система суммирует MealEntry и WaterEntry за дату.
  3. Система отображает итоги и прогресс относительно целей.
- **Постусловия:** итоги отображены.
